語言模型煉成——從機率預測到 RLHF 對齊

M6 拆開了 Attention 怎麼「算」出一個位置的輸出向量；這個模組要接著回答：這整套 Transformer 具體是怎麼被「訓練」出來的——從一堆網路文字，怎麼變成 GPT／BERT／T5，又怎麼被 SFT 跟 RLHF／DPO 調教成一個聽得懂指令、講話有分寸的 Claude。這是你目前只會「呼叫」API、答不出訓練原理的最大缺口。

01　為什麼要學這個

M6 已經拆開 Attention 怎麼「算」；這個模組要接著回答：這整套架構具體是「怎麼被訓練」出來的——從一堆網路文字，怎麼變成會接龍的 GPT、會理解的 BERT、統一處理任務的 T5，又怎麼再被 SFT 跟 RLHF／DPO，調教成一個聽得懂指令、講話有分寸的 Claude。這是你「只會呼叫 Claude API、答不出訓練原理」的最大知識缺口，也是面試被電最兇的一塊。

02　底層概念（先不談任何架構、任何案例）

完全先不談 GPT、不談 BERT、更不談你的 Threat Intel Agent，只談一件最底層的事：語言模型的本質，是在做條件機率預測。給一句殘缺的話：「今天天氣真___」，問你「空格最可能填什麼字」，人腦其實就是在對候選字各自估一個機率，選機率最高的那個。

候選字直覺機率意義
好0.40最常見的接法，機率最高
棒0.30次常見，語意接近「好」
差0.05語法通，但不是多數人會選的字
爛0.02可能但少見
（其他所有字）0.23剩下機率分給詞彙表裡其他幾萬個字

寫成數學符號就是 P(xᵩ | x₁, x₂, ..., xᵩ₋₁)——給定前面已經出現的字，估計下一個字的機率分布。語言模型做的事，本質上就是一直在重複這個機率預測的動作，只是它不是靠人腦直覺，而是用一個巨大的神經網路（M4／M5 學過的那套）去估計這個分布，而且候選字不是 4 個，是幾萬個 token。

再回頭看第①層「預訓練」：GPT／BERT／T5 三種架構，其實是在「猜什麼」這件事上做了不同選擇——

架構預訓練在猜什麼代表模型擅長任務
GPT（Decoder-only）CLM：只看左邊，猜下一個字（自迴歸接龍）GPT系列、ChatGPT生成、對話、續寫
BERT（Encoder-only）MLM：遮 15% 的字猜回來，＋NSP 判斷兩句是否連貫（雙向）BERT、RoBERTa分類、理解、抽取（情感分析、NER）
T5（Encoder-Decoder）Span-corruption：整段挖空猜整段，任務前綴統一成文字轉文字T5、BART摘要、翻譯、跨任務統一處理

延伸一種目標函數：Contrastive Loss（如 CLIP），猜的不是「字」而是「這兩者搭不搭」——判斷一張圖跟一段文字是否相符，用在圖文配對任務。

順帶一提，GPT 生成時每一步都要從步驟 02 那張機率分布表裡「抽一個字出來」，抽法本身也有好幾種策略：

策略做法特性
Greedy Search每一步都選機率最高的字簡單快速，但容易單調重複
Beam Search同時保留 k 條候選序列，最後選整體機率最高的品質較穩，但計算成本隨 k 倍增
Top-K 採樣只從機率最高的 k 個字裡隨機抽保留隨機性，但 k 固定，可能漏掉合理的字
Top-P（Nucleus）採樣從累積機率達 P 的字集合裡隨機抽候選集合大小動態變化，比 Top-K 更靈活
Temperature調整機率分布的平滑程度越高越隨機有創意，越低越保守貼近最高機率選項
04　現在才代入具體案例——非結構化文字版

三層機率調整都疊好了，這時候才代入你的貫穿案例——但這次要換成 M1-M5 處理不了的版本。前面的結構化特徵（WHOIS 欄位、IP 信譽分數、國別代碼）都是現成的數值／類別欄位，丟進分類器就能訓練。現在丟給你一段真實世界常見的 Abuse Report 全文：

「該IP過去30天內被回報多次嘗試SSH暴力破解，地理位置與過去合法登入紀錄不符，但WHOIS顯示為知名雲端服務商IP段。」

這段話沒有任何現成的數值欄位可以直接餵給 M1-M5 那種分類器——「過去30天內被回報多次」「地理位置不符」「但是知名雲端服務商」這幾個線索之間的因果與轉折關係（「但」字帶來的語意反轉）必須靠「讀得懂上下文語意」的能力才抓得出來。這正是需要一個已經在海量文字上做過預訓練、具備語言理解能力的 LLM 才處理得了的輸入型態——而這正是你的 Threat Intel Agent 目前在做的事：Claude 接住這段非結構化文字，直接判斷風險。但要老實面對一個事實：你只是在「呼叫」一個別人已經預訓練＋SFT＋對齊好的模型，你自己完全沒有做過微調或 RLHF——這正是這個模組要幫你補的原理缺口。

05　類比鎖記憶——用你熟悉的部署／維運類比

機制都懂了，現在才用後端工程師的語言幫記憶打結：

預訓練 Pre-training ≈ 建置一個通用 Base Image　　什麼服務都懂一點，但沒特化任何業務邏輯 SFT 監督微調 ≈ 從 Base Image 客製化出服務 Image　灌進特定的 API 合約（問答/指令格式） RLHF/DPO 對齊 ≈ 上線前的 Code Review + Staging 驗收　依人類偏好調整最終要 deploy 的版本

再往下一層：Reward Model ≈ 一個學會模仿人類 Reviewer 打分的自動化 Linter／CI Gate，它自己不是真理，只是預測「人類大概會怎麼評」。PPO 裡的 KL 散度懲罰項 ≈ 你做 Canary Rollout 時設的「變更幅度限制」——新版本（對齊後的模型）不能跟舊版本（SFT 模型）差太多，差太多代表可能有破壞性變更（模型為了拿高分亂講話、脫離常識）。而 DPO 最大的意義，是把「Reward Model + PPO」這一整套要同時維護 Actor／Critic／Reward／Reference 四個模型的複雜 Pipeline，簡化成「Chosen vs Rejected」的 pairwise 比較，直接算一個 loss 更新——像是把一條要維護四個微服務的 CI/CD Pipeline，簡化成一支直接算勝負的 A/B Test 腳本。

07　業界實際應用案例

你的資安分類只是一個練手案例；面試被問「這技術實際用在哪裡」，要答得出真實產品：

技術具體產品／系統解決了什麼問題
GPT 系列（Decoder-only）ChatGPT、GitHub Copilot自迴歸生成讓模型能連續產出完整文章、對話、程式碼，而不只是分類或抽取。
BERT（Encoder-only）Google 搜尋排序雙向理解查詢語意（例如「銀行」是金融機構還是河岸），改善搜尋結果排序準確度。
T5（Encoder-Decoder）Google 的摘要／翻譯類服務統一用「文字轉文字」格式處理多種任務，同一套模型不用為每個任務重新設計架構。
RLHF 對齊ChatGPT、Claude、Gemini幾乎所有主流對話式 AI 都用 RLHF 或類似技術做對齊，避免模型亂講話或講出危險內容。
你的 Threat Intel Agenttool_choice 強制輸出結構化 JSONClaude 能穩定生成結構化風險報告而不是亂回答，某種程度上正是依賴 Anthropic 已經做過的 SFT 與對齊訓練，讓它拿到強制指令時能可靠照格式輸出。
08　名詞卡（後端翻譯詞典）
預訓練Pre-training

建置一個通用 Base Image 的階段——什麼服務都懂一點，但還沒特化任何業務邏輯。

監督微調SFT

從 Base Image 客製化出服務 Image，灌進「問答／指令」這套 API 合約，讓模型從「接龍」變成「聽得懂需求」。

人類反饋強化學習RLHF

上線前的 Code Review + Staging 驗收——用人類偏好調整最終要 deploy 的版本。

直接偏好優化DPO

把「Reward Model + PPO」四個模型的 Pipeline，簡化成一支直接算 Chosen vs Rejected 勝負的 A/B Test 腳本。

獎勵模型Reward Model

學會模仿人類 Reviewer 打分的自動化 Linter，自己不是真理，只是預測「人類大概怎麼評」。

KL 散度懲罰KL Penalty

Canary Rollout 時設的「變更幅度限制」——新版本不能跟舊版本（SFT 模型）差太多，避免破壞性變更。

上下文學習In-Context Learning

不用重新 deploy、不用 retrain，只靠這次 request 裡帶的 Few-shot 範例，模型現學現賣。

對齊稅Alignment Tax

跑完一輪「安全性 regression 測試」後，某些原本正常的功能（常識／翻譯）效能反而下降的副作用。

09　面試模擬

Q：RLHF 跟 DPO 的差別是什麼？為什麼近期很多團隊改用 DPO？

A（草稿）：「RLHF 是三階段流程：先 SFT 訓練出一個聽得懂指令的初始模型，再讓人類對同一輸入的多組回答做偏好排序，拿排序資料訓練一個 Reward Model 去預測人類偏好，最後用 PPO，讓 LLM（當作 policy）生成文字，由 Reward Model 打分當獎勵訊號更新參數，同時加一個 KL 散度懲罰項限制新模型跟原本 SFT 模型差太多。整套流程要同時維護 Actor、Critic、Reward、Reference 四個模型，訓練複雜也不穩定。DPO 則是跳過『訓練獨立 Reward Model + PPO 強化學習』這一整套，直接拿人類標好 Chosen／Rejected 的成對資料，用一個交叉熵損失函數同時拉高好答案、壓低壞答案被生成的機率，只需要正在訓練的模型加一個 Reference 模型共兩個，把 2-3 個訓練階段簡化成 1 個，而且實驗上同等 KL 散度水準下 Reward 反而更高。拉回我自己的 Threat Intel Agent——我目前完全沒有自己做微調或對齊，是直接呼叫 Claude API，靠的是 Anthropic 已經幫我做好的 SFT + 對齊。我用 tool_choice 強制它在第二輪一定要呼叫 submit_report，能穩定拿到結構化 JSON 而不是模型亂回答，某種程度上就是在吃 Claude 背後 SFT 訓練的紅利——它已經被訓練成『看到明確指令格式，就會照做』，而不是還停留在『純接龍，想到哪寫到哪』的預訓練模型狀態。」

10　效率檢查點

合上這頁，只憑步驟 06 那張心智圖（不看文字），把「地基→預訓練→SFT→對齊」以及 GPT／BERT／T5 各自差在哪個節點，重新講一次給自己聽。RLHF 三步驟（SFT→RM→PPO）跟 DPO 省略了哪兩個模型，也要能脫稿講出來，才算真的疊上去了。
