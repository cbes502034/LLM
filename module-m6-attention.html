Attention 機制——LLM 的引擎

你的 Threat Intel Agent 靠 Claude API 判斷「這個 IP 危不危險」，Claude 內部到底怎麼「看懂」你丟進去那一大段查詢結果？這個模組從向量內積這個最底層的動作開始，一路疊到 Transformer 一整層的架構，拆開你目前只會呼叫、不懂內部的黑盒子。

01　為什麼要學這個

你的 Threat Intel Agent 靠 Claude API 判斷「這個 IP 危不危險」，Claude 內部到底怎麼「看懂」你丟進去那一大段查詢結果？答案就是 Attention——這個模組拆開這顆你目前只會呼叫、不懂內部的黑盒子。

02　底層概念（先不談案例，只談最原始的東西）

Attention 骨子裡只有一個數學動作：算兩個向量像不像。文字要先變成向量（詞嵌入，見下方名詞卡），而「像不像」最基本的算法叫內積（dot product）——把兩個向量對應維度相乘再全部加總。數字越大代表方向越接近，數字是 0 代表毫無關係，負數代表方向相反。

例子向量 a向量 ba·b（相似度分數）意義
方向接近(1, 2)(2, 1)1×2 + 2×1 = 4分數高 → 兩者「有關」
完全垂直(1, 2)(−2, 1)1×(−2) + 2×1 = 0分數 0 → 兩者「無關」
方向相反(1, 2)(−1, −2)1×(−1) + 2×(−2) = −5負分 → 兩者「相斥」

這就是地基。Attention 裡最核心的 q·k，做的就是這件事——完全還沒牽扯到「文字」「句子」「Threat Intel」，純粹是兩串數字的內積。

04　現在才代入具體案例

地基跟流程都蓋好了，這時候才套進你熟悉的東西：一句話丟進模型——「IP 1.2.3.4 在 AbuseIPDB 被回報 42 次，但地理位置在台灣。」模型在算「危險」這個判斷時，「42 次」這個詞的向量會去跟句子裡每個字的向量做內積（步驟 02 的地基），分數高的字（可能是「回報」「42」）會在 Softmax 後拿到較大權重，最終輸出向量會比較貼近「42 次回報」而不是「台灣」。案例在這裡的作用，是驗證你懂不懂上面五格，不是用來理解機制本身。

05　類比鎖記憶——用 SQL JOIN 掛住五格

機制已經懂了，現在才用類比幫長期記憶打個結：

Query（Q） ≈ WHERE 子句裡你要比對的值　　　　　　「我在找什麼」 Key（K） ≈ 對方資料表拿來被 JOIN 比對的欄位　　「我有什麼可以被找到」 Value（V） ≈ JOIN 成功後真正要 SELECT 出來的欄位　「找到後真正要拿的資料」

跟 SQL JOIN 最大的不同：JOIN ON 是 0／1 的篩選，符合條件就撈出來、不符合就丟掉；Attention 是步驟 03 那張圖裡的「連續加權平均」——所有字都被撈出來，只是權重不同。這正是 Transformer 能「模糊地」理解上下文、而不是死板比對關鍵字的原因。

08　名詞卡（後端翻譯詞典）
詞嵌入Embedding

把文字轉成的正規化 ID——像把使用者字串轉成資料庫裡的 user_id，只是這裡的 ID 是幾百維的浮點數向量，語意相近的字，向量內積也較大。

自注意力Self-Attention

句子裡每個字都對其他所有字做一次加權 JOIN，決定生成這個字時該多聽誰的意見。

多頭注意力Multi-Head Attention

同時開好幾條並行連線，各自用不同條件做 JOIN——像同時查「地理位置關聯表」跟「信譽分數關聯表」，最後把結果併在一起。

位置編碼Positional Encoding

Attention 本身不知道字的順序，就像 JOIN 出來的 result set 沒有預設排序——位置編碼是額外塞進去的一個「原本第幾筆」欄位。

09　面試模擬

Q：你了解 Transformer 的 Attention 機制嗎？

A（草稿）：「Attention 的地基是向量內積——衡量兩個向量方向像不像。往上疊，每個 token 會投影出 Query、Key、Value 三組向量，Query 跟每個 Key 做內積得到相似度分數，分數經過 Softmax 轉成加總為 1 的權重，再對 Value 做加權平均，得到這個位置的輸出。這其實跟資料庫的 JOIN 概念很像，差別是 JOIN 是離散篩選、符合條件才撈出來，Attention 是連續的加權平均，所有位置都會被納入計算，只是權重不同。這也是為什麼 Transformer 能處理『模糊』的上下文關係，而不是死板比對關鍵字。」
