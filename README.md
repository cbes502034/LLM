## 第一章演算法速查表

正文每個演算法都是「底層概念→流程圖→逐步講解→具體例子→業界應用實例」的完整走法，這裡只列速查用的總表：名稱、應用場景、時間複雜度、優缺點。時間複雜度是理論上的量級估計，實際效能還要看資料本身的分布與實作方式，僅供判斷「資料量大時哪個方法會先變慢」的直覺參考（n＝訓練樣本數、d＝特徵數、t＝樹或弱分類器的數量、s＝支持向量的數量、c＝類別數）。

| 名稱 | 應用場景 | 訓練時間複雜度 | 預測時間複雜度 | 優缺點 |
|---|---|---|---|---|
| **線性迴歸**<br>Linear Regression | 預測連續數值：房價、銷量、氣溫、需求預測 | O(n·d²)（正規方程）或每輪 O(n·d)（梯度下降） | O(d) | 優：簡單快速、係數可直接解釋每個因素的影響力。<br>缺：只能抓線性關係，資料若是曲線關係會擬合不良。 |
| **Logistic Regression**<br>邏輯迴歸 | 信用風險評分、廣告點擊率預估、二元分類且需要機率輸出的場景 | 每輪 O(n·d)，需迭代到收斂 | O(d) | 優：輸出是機率不只是類別、可解釋性高、訓練快。<br>缺：只能抓接近線性的決策邊界，遇到複雜非線性關係表現有限。 |
| **決策樹**<br>Decision Tree | 需要把判斷邏輯攤開給非技術人員看的場景，如醫療輔助診斷、審核規則 | 約 O(n·d·log n) | O(log n)（樹深度） | 優：規則直覺好理解、不需要特徵標準化。<br>缺：單棵樹容易過擬合，資料稍變樹的形狀可能大幅改變（不穩定）。 |
| **Random Forest**<br>隨機森林 | 特徵多、需要穩定準確度優先於極致可解釋性的場景，如醫療影像、生物資訊特徵重要性分析 | O(t·n·d·log n) | O(t·log n) | 優：比單一決策樹穩定、抗雜訊、可評估特徵重要性。<br>缺：模型較大、佔記憶體，不如單棵樹好逐步解釋給別人聽。 |
| **AdaBoost**<br>自適應提升 | 資料相對乾淨、想從一堆弱模型榨出更高準確度的場景，Kaggle 競賽常見 | O(t·n·d) | O(t) | 優：準確度通常優於單一模型，理論保證穩固。<br>缺：對雜訊資料敏感（會過度關注錯誤樣本）、訓練是序列化的，較難平行化。 |
| **KNN**<br>K-最近鄰居 | 資料量不大、決策邊界不規則、推薦系統的相似項目查找 | O(1)（只是儲存資料，沒有真正訓練） | O(n·d)（暴力法，需跟全部資料比對距離） | 優：邏輯直覺、不需要訓練、天生適合處理不規則邊界。<br>缺：資料量大時每次預測都很慢，且對特徵尺度／單位敏感，須先標準化。 |
| **SVM**<br>支持向量機 | 特徵維度高但樣本數不算巨大的場景，如文字分類、生物資訊基因分類、早期人臉辨識 | O(n²)～O(n³)（視實作與 Kernel 而定） | O(s·d) | 優：高維度資料表現好、理論基礎扎實、Kernel trick 可處理非線性。<br>缺：樣本數一大訓練就明顯變慢，Kernel 與其參數需要實驗調整。 |
| **貝氏分類器**<br>Naive Bayes | 文字分類（垃圾郵件、新聞分類）、需要極快訓練與預測速度的場景 | O(n·d) | O(c·d) | 優：訓練與預測都極快、小資料量也能用、對文字分類效果穩定。<br>缺：「特徵互相獨立」的假設在真實資料中常不成立，機率估計可能失準。 |
