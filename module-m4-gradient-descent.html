梯度引擎——神經網路怎麼學會調整自己

你的 Threat Intel Agent 目前是呼叫 Claude API 做判斷；如果之後想做一個本地端輕量神經網路分類器初篩 IP 風險，背後真正在「訓練」這個網路的，就是這套機制。這個模組拆開 PyTorch 訓練一顆網路時，底層到底在算什麼。

01　為什麼要學這個

面試被問「你知道神經網路怎麼訓練的嗎」，如果只能答「loss.backward() 然後 optimizer.step()」，面試官會繼續往下追——答不出「為什麼這樣做有效」，就會被抓包只是在背 API 呼叫順序。這個模組要打通梯度、Tensor、Autograd 這三個訓練一顆神經網路時最底層、也最常被追問設計原理的機制。

02　底層概念（先不談案例，只談最原始的東西）

完全先把 AI、神經網路、loss 放一邊。從國高中數學的斜率（導數）開始：一元函數 y = x²，在某一點的切線斜率，代表「如果 x 稍微增加一點點，y 會怎麼變」。這件事跟 AI 沒有任何關係，純粹是一條曲線在某一點的傾斜程度。

位置xy = x²x + 0.1y'斜率 ≈ Δy/Δx
較平緩處111.11.212.1（理論值 2x = 2）
中段393.19.616.1（理論值 2x = 6）
較陡處5255.126.0110.1（理論值 2x = 10）

斜率本身也是一個會隨位置變化的數字——x 越大，曲線越陡，斜率也越大。這就是梯度的地基：「如果我稍微調整一個數字，結果會往哪個方向、變化多快」。深度學習裡的「梯度」，說穿了就是把這個斜率，從一個變數推廣到成千上萬個變數（模型裡的每一個權重），每個權重各自有一個屬於自己的斜率。

03　逐層往上疊——從斜率到參數更新

地基蓋好，一步步加元件。單一變數的斜率，推廣到多個參數時，每個參數各自算一次偏微分（∂E/∂w），把所有參數的偏微分合起來，就叫做梯度向量（gradient）。梯度向量的方向是 loss 上升最快的方向；要讓 loss 變小，就把參數往這個方向的反方向移動。梯度下降的核心邏輯只有一句話：「沿著讓 loss 變小的方向，把參數往那個方向移動一小步，重複很多次」——不是解方程式一次得到答案，是像二分搜尋一樣，一步一步逼近。

疊代輪次目前 wLoss梯度 ∂E/∂wΔw = −η·∂E/∂w（η=0.1）下一輪 w
第 1 輪0.508.202.0−0.200.30
第 2 輪0.305.101.5−0.150.15
第 3 輪0.152.900.7−0.070.08
第 4 輪0.081.620.3−0.030.05
第 5 輪0.051.350.1−0.010.04（loss 幾乎不再下降 → 視為收斂）

loss 從 8.2 一路逼近到 1.3 附近就幾乎不再下降，代表已經接近這個問題的最低點。這裡的 η（學習率）若設太大（例如設成 2 而不是 0.1），每次調整的 Δw 會過大，w 可能在最低點兩側來回震盪甚至越調越糟（發散）；η 設太小，則要跑非常多輪 loss 才會有感的下降。深層網路若用 sigmoid 活化函數，反向傳播時梯度會一層層越乘越小，前面幾層幾乎學不到東西，這叫梯度消失（Vanishing Gradient），現代 DNN 多改用 ReLU 緩解這個問題。

04　現在才代入具體案例

地基跟流程都蓋好了，這時候才套進「這個 IP 是不是威脅」的貫穿案例。跟 M1／M2 的傳統 ML 用的是同一組結構化特徵——AbuseIPDB 分數、地理位置（編碼過的類別特徵）、PortScan 次數——但這次不是人工挑規則、也不是決策樹自己切分特徵空間，而是丟進一個小型神經網路，讓每一層的權重透過梯度下降自動學出「這三個特徵要怎麼組合」才能準確判斷是否為威脅。

套用 03 步驟的疊代表格來看：假設 w 代表隱藏層裡「AbuseIPDB 分數」這個輸入的權重，一開始隨機初始化 w=0.5，模型看過一批 IP 資料後算出 loss=8.2（預測跟正解差很多），backward() 算出這個 w 的梯度是 2.0，更新後 w 變成 0.3⋯跟表格裡的數字完全一樣，只是現在它有了意義——它是「AbuseIPDB 分數該被賦予多大權重」這個真實參數。

這就是「換神經網路做」的核心差異：M1／M2 的邏輯迴歸或決策樹，特徵組合方式是人工設計或演算法用固定規則切分；這裡是讓梯度下降在數千筆 IP 樣本上，自動把 w 調整到「AbuseIPDB 分數的重要性大概是地理位置的兩倍」這種組合方式，不用自己寫 IF-ELSE 規則。

05　類比鎖記憶——用後端維運場景掛住四個名詞
Tensor ≈ 可以丟到不同運算後端（CPU/GPU）執行的通用資料容器 　一份程式碼、不用管底層機器，像把運算邏輯包成可部署到本地或雲端GPU的service Autograd計算圖 ≈ 分散式追蹤（tracing）——request經過每層middleware時自動記錄一個span 　正向傳播時系統偷偷記下每一步操作，backward()才沿著這條span鏈路往回算梯度 梯度下降 ≈ 效能調優時反覆調整一個config值（如DB連線池大小），觀察指標有沒有變好 　一次調一點，不要一次梭哈 學習率η ≈ 你每次調整config值的「步伐大小」 　調太大系統直接震盪不穩定，調太小要observe很多輪才看得出效果

最大的差異：tracing 工具通常是給你「看」的，Autograd 的計算圖記錄下來是為了「自動幫你算數學」——這是它跟一般 distributed tracing 最大的不同，但「正向執行時默默記錄、之後才回放」這個設計精神是共通的。

07　業界實際應用案例——這技術實際用在哪裡

你的資安分類只是一個練手案例；面試被問「梯度下降有什麼應用」，要答得出真實產品，不能只講自己這一個小例子：

應用領域具體產品／系統梯度下降解決了什麼問題
影像辨識ResNet 等 CNN 模型訓練用梯度下降疊代調整數百萬個卷積核參數，讓模型從像素中自動學出邊緣、紋理、物體的層次特徵。
推薦系統電商／影音平台的 Embedding 訓練用同一套機制訓練使用者與商品的向量表示，讓內積相近的商品被判定為相似。
大型語言模型GPT 等 LLM 的預訓練階段模型規模到千億參數，本質上仍是同一套 forward → backward → 更新的迴圈，只是規模跟算力差了好幾個量級。
你的 Threat Intel Agent（延伸）本地端輕量 NN 分類器初篩 IP 風險若想用小模型先過濾掉明顯安全的 IP，省下呼叫 Claude API 的成本與延遲，訓練這個小模型用的正是這套機制。

共同點：不管模型是幾層的小型分類器，還是千億參數的 LLM，「用梯度下降不斷調整參數讓 loss 變小」這件事沒有例外——差別只在於要調整的參數數量，以及算力跟工程上怎麼把這套迴圈跑得動。

08　名詞卡（後端翻譯詞典）
張量Tensor

PyTorch 的基本資料容器，概念上像 NumPy 的 ndarray，但多一個能力：可以丟到 GPU 上算——像把運算 service 設計成可在本地或雲端 GPU 機器上部署，一份程式碼、不同運算後端。

自動微分Autograd

requires_grad=True 後，正向傳播時 PyTorch 偷偷記錄每一步操作（建計算圖），像分散式追蹤系統在 request 經過每層 middleware 時自動記 span，之後才能回放算出每一段的梯度。

梯度下降Gradient Descent

沿著讓 loss 變小的方向，一小步一小步調整參數——像效能調優時反覆調整一個 config 值，一次調一點，看指標有沒有變好，不要一次梭哈。

梯度消失Vanishing Gradient

梯度反向傳播經過太多層 sigmoid，越乘越小，傳到最前面幾層時幾乎沒訊號——像一個 request 經過太多層代理／中介轉發，訊號每經過一層就衰減一點，傳到源頭時幾乎讀不到了。

09　面試模擬

Q：你能解釋一下 PyTorch 的 Autograd 是怎麼運作的嗎？為什麼 PyTorch 被稱為動態計算圖？

A（草稿）：「把一個 Tensor 的 requires_grad 設成 True 後，PyTorch 在正向傳播的過程中，每做一次運算就會自動建立一個 Function 節點，記錄這個操作跟它的輸入，連起來就變成一張計算圖。呼叫 loss.backward() 時，系統會沿著這張圖用鏈式法則反向傳播，把每個參數的梯度算出來存進它的 .grad 屬性，拿去給 optimizer 更新。PyTorch 屬於 define-by-run 的動態計算圖，是因為這張圖是程式實際執行的當下才建立的，不是像早期 TensorFlow 那樣要先把整張圖定義好才能跑——這讓我可以在 forward 裡直接寫 Python 的 if/for，彈性很高，代價是每次迭代都要重新建圖，效能上會比先定義好的靜態圖稍差一點。如果之後我想做一個本地端小型 NN 來初篩 IP 風險、省掉一部分 Claude API 呼叫，背後訓練這顆網路用的就是這套機制，而推論階段我會記得用 torch.no_grad() 包起來，不需要梯度追蹤，省記憶體也省算力。」
