強化學習地圖——只為看懂 PPO 在 RLHF 裡幹嘛

M7 提到 RLHF 第三步用 PPO 演算法優化模型，這個模組不打算把你變成強化學習專家——只求你查得到、講得出：PPO 是什麼、站在整條技術脈絡的哪個位置、跟 RLHF 怎麼接起來。

01　為什麼要學這個

這是一個選修・查閱模組。目的只有一個：看懂 M7 提到的 PPO，在 RLHF 第三階段裡到底扮演什麼角色——不是要你精通整套強化學習理論、不是要你會推導 Bellman 方程式的證明。查得到、講得出，這個模組的任務就完成了。

02　底層概念——訓練一隻狗坐下

完全不談任何公式，先想一個最生活化的畫面：訓練一隻狗坐下。你（訓練者）看牠現在的姿勢，喊一聲指令，牠做出某個動作——坐下了，給牠一塊零食；亂跑，什麼都不給。重複幾百次之後，狗會自己摸索出「什麼動作能拿到零食」，開始更常做出那個動作。這整個過程裡有五個角色：

角色英文狗狗訓練裡對應誰
代理人Agent那隻狗——做決策、採取動作的一方
環境Environment狗所處的房間＋你這個訓練者
狀態State狗目前的姿勢、位置、剛聽到的指令
動作Action坐下、亂跑、吠叫……狗能做的各種行為
獎勵Reward零食（做對）或什麼都沒有（做錯）

這是一種試錯式（trial-and-error）學習——沒有人事先給狗一份「正確動作對照表」，牠靠不斷嘗試、觀察結果，自己摸索出策略。這跟前面 M1-M7 那種「有一堆輸入輸出配對資料」的監督式學習，完全是不同邏輯。

03　RL 知識地圖——PPO 站在哪裡

不需要每個節點都展開公式，只要知道這條脈絡怎麼一路走到 PPO、又怎麼接上 RLHF：

兩個附帶概念，查得到就好：On-policy（邊互動邊學習，只能用自己目前策略收集的資料訓練自己）vs Off-policy（可以用別的策略收集到的資料訓練，資料能重複使用，效率較高）——PPO 正是 Policy Gradient 的 Off-policy 延伸版本，這也是它比純 Policy Gradient 更省樣本的原因。策略函數 π，指的是「在某個狀態下，決定要採取什麼動作的機率分布」——沒錯，跟 M7 步驟 02 那個「猜下一個字」的機率分布，是同一種數學物件。

04　代入 RLHF 情境

把上面地圖裡的 Agent/Environment/State/Action/Reward，直接對應到 M7 講的 RLHF 第三階段：

Agent（代理人） ≈ LLM 本身 Policy（策略π） ≈ LLM 目前的參數——決定「看到這段上下文，該生成什麼字」 Action（動作） ≈ LLM 產生一段回覆 Reward（獎勵） ≈ Reward Model 對這段回覆打的分數 PPO 在做的事 ≈ 在「不要跟原本SFT模型差太多」的前提下， 調整LLM參數，讓它更常做出高Reward的回覆

貝爾曼方程式 V(S) = max_a(R(S,a) + γV(S')) 的 γ（折扣因子），概念上類似機器學習裡的 learning rate——決定模型有多重視「未來」的獎勵。你不需要會推導這條式子怎麼來的，知道它在定義「一個狀態的價值＝當下最好動作的獎勵＋打折後下一狀態的價值」就夠用。

延伸一個小表格，強化學習除了 RLHF 之外實際用在哪裡（點到為止，不用展開太多）：

領域具體案例備註
對齊 LLMChatGPT、Claude、Gemini 的 RLHF/PPO本模組的核心情境
遊戲 AIAlphaGo、玩 Atari 遊戲的 DQNReward 是輸贏或遊戲分數，不是人類偏好
機器人控制機械手臂抓取、步態控制Reward 通常是任務完成度或動作平穩度

一個延伸思考（點到為止，不用寫得太篤定）：如果之後想讓你的 Threat Intel Agent 的查詢策略本身也被優化——例如讓它自動學會「先查哪個情資來源最有效率、最省 API 額度」——這也是強化學習可能可以發揮的方向，Reward 可以設計成「查詢成本」與「判斷準確度」的權衡。

05　面試模擬

Q：RLHF 裡的 PPO 在做什麼？為什麼要加 KL 散度懲罰？

A（草稿）：「PPO 是 Policy Gradient 的 Off-policy 改良版，用在 RLHF 第三階段：LLM 本身就是要優化的 policy，它生成一段回覆算是一個 action，Reward Model 對這段回覆打分當作 reward。PPO 的工作是根據這個 reward 訊號調整 LLM 參數，讓它更常生成高分的回覆；但如果放任它一路優化，模型可能會學到『鑽 Reward Model 漏洞』的取巧回答方式，講出脫離常識、甚至危險的內容去騙高分。所以 PPO 額外加一個 KL 散度懲罰項，限制更新後的模型跟原本 SFT 模型的差異不能太大，等於是幫這次更新設一個『安全邊界』。這跟我在維運上熟悉的 Canary Rollout 概念很像——不會一次讓新版本全量上線，而是限制它跟舊版本的差異幅度，出事時影響可控。」

06　效率檢查點

閉上眼睛，只憑步驟 03 那張地圖，把 MDP→Bellman→Q-Learning→Policy Gradient→PPO→RLHF 這條線重新講一次，並且能講出 PPO 加 KL 懲罰的理由。講得出來，這個查閱模組就算過關，不需要再往下鑽。
