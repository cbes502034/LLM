決策森林——從一句「哪個問題先問」長成一片樹林

如果想在呼叫昂貴的 Claude API 之前，先做一層本地端快速初篩，決策樹家族會是第一個被面試官考的選項。這個模組從「亂不亂」這個最原始的直覺開始，一路疊到決策樹、隨機森林、AdaBoost，讓你不只會 .fit()，還能講出「為什麼這棵樹先問這個欄位」。

01　為什麼要學這個

決策樹跟集成方法（Random Forest / AdaBoost / XGBoost）是面試熱度最高的傳統 ML 主題之一，幾乎是必考題。而且它不只是拿來考試——如果你想幫 Threat Intel Agent 做一個「先自己篩一輪，看起來明顯安全就不用花錢呼叫 LLM」的本地分類器，決策森林家族會是合理的第一個候選。

02　底層概念（完全不談決策樹，只談「亂不亂」）

決策樹跟隨機森林骨子裡都在做同一件事：想辦法把一堆「亂糟糟」的東西，切到「越來越乾淨」為止。先完全不提決策樹，只看三個袋子裡的球：

袋子內容物你能一次就猜對摸出來的顏色嗎？亂度 I
袋子 A8 顆球，全部紅色能，閉著眼睛猜都對I = 0
袋子 B8 顆球，6 紅 2 藍大致猜得到，但偶爾會錯I ≈ 0.81
袋子 C8 顆球，4 紅 4 藍完全猜不準，對半開I = 1

這個「猜不猜得準」的直覺，寫成公式就是 Shannon 資訊理論裡的亂度（Entropy）：

I(p,n) = -Σ (pᵢ/(p+n)) · log2(pᵢ/(p+n)) 袋子A：I = -(8/8)log2(8/8) - (0/8)log2(0/8) = 0 袋子B：I = -(6/8)log2(6/8) - (2/8)log2(2/8) ≈ 0.31+0.50 = 0.81 袋子C：I = -(4/8)log2(4/8) - (4/8)log2(4/8) = 0.5+0.5 = 1.00

全部同色＝零不確定性＝亂度最低；對半分＝最不確定＝亂度最高（二元分類下的最大值是 1）。這就是整個模組的地基，完全還沒有決策樹，也還沒有任何 IP。

03　逐層往上疊——從亂度到一次真正的分裂

決策樹由三種元件組成：中間節點（一個測試條件）、分支（條件的答案）、葉節點（最終分類結果），用貪婪演算法由上而下一路遞迴分割，屬性需要是類別型（連續值要先離散化）。先看純結構：

選屬性的公式叫資訊獲利（Information Gain，ID3/C4.5 演算法用）：

Gain(A) = 分裂前的亂度 - 分裂後的加權亂度

連續數值屬性（例如分數型欄位）常改用 Gini 索引：Gini(D) = 1 - Σpⱼ²，選讓分裂後加權 Gini 最小的分割點。概念上跟亂度一樣是在衡量「不純度」，只是計算公式不同，CART 演算法常用它。

現在用一組簡化過的、真的關於 IP 特徵的 5 筆小資料，手算一次完整流程——這是地基跟案例第一次交會的地方：

IP屬高風險國家？PortScan次數>10？實際是否為威脅
IP-1是是威脅
IP-2是否威脅
IP-3是是威脅
IP-4否是安全
IP-5否否安全
母集合：5筆，3威脅／2安全 → I(3,2) = 0.971 【屬性A：屬高風險國家？】 　是（3筆，3威脅0安全）→ I=0 　否（2筆，0威脅2安全）→ I=0 　加權亂度 = (3/5)×0 + (2/5)×0 = 0 　Gain(A) = 0.971 - 0 = 0.971　← 完美分裂 【屬性B：PortScan次數>10？】 　是（3筆，2威脅1安全）→ I≈0.918 　否（2筆，1威脅1安全）→ I=1 　加權亂度 = (3/5)×0.918 + (2/5)×1 ≈ 0.951 　Gain(B) = 0.971 - 0.951 ≈ 0.02　← 幾乎沒分開 結論：優先選「屬高風險國家？」分裂，Gain(0.971) 遠大於 PortScan 的 Gain(0.02)。

真實資料不會這麼乾淨，樹如果長得太深，會為了遷就一兩筆怪樣本切出過度細碎的分支——這就是過擬合，解法是修剪：預先修剪（建構過程中提前停止，例如限制最大深度）跟事後修剪（先長成完整樹，再剪掉貢獻不大的分支）。

04　現在才代入完整案例

03 步驟已經用 5 筆 IP 資料選出第一個分裂屬性，這裡把案例再延伸完整一點。假設你還想拿 AbuseIPDB 分數（連續值）當分裂屬性，就改用 Gini 索引找分割點：母集合 Gini(D) = 1 - ((3/5)² + (2/5)²) = 0.48；如果切在「分數 ≥ 50」，剛好跟高風險國家那組完全對齊（3筆全威脅、2筆全安全），兩邊加權 Gini 都是 0——在這個簡化案例裡，AbuseIPDB 分數跟地理位置高度相關，兩種屬性切出來一樣乾淨，實務上你就是分別算 Entropy 版的 Gain 跟 Gini 版的不純度下降量，兩邊都算一次再挑最好的。

過擬合在這個案例裡長這樣：如果樹繼續往下切到「PortScan=13 且分數=37 且國家=XX」才判定為威脅，這種branch 只服務資料集裡的某一筆 IP，換一批新 IP 進來完全用不上——這時候限制 max_depth（預先修剪）或訓練完再剪掉這種單樣本分支（事後修剪），是實務上避免模型「記住訓練資料」而不是「學到規律」的做法。

05　類比鎖記憶——決策樹是 if/elif，集成方法是分散式架構
決策樹 ≈ 一長串巢狀的 if/elif/else（或SQL的CASE WHEN），一條路徑走到底就是一個判斷結果 Bagging ≈ 對同一張資料表做多次「取後放回」的隨機抽樣，像重複執行帶RANDOM()的SELECT，各自訓練一個獨立模型 Random Forest ≈ 多台worker掛在同一個load balancer後面，每台worker連看到的欄位都不完全一樣，最後用投票決定回應 Boosting ≈ 連續好幾輪的code review：這輪漏掉的bug（誤判樣本），下一輪reviewer被要求特別盯著看 AdaBoost ≈ Boosting的其中一種實作，明確調高上輪答錯樣本的權重，像把上次失敗的test case標記high priority優先重跑 修剪Pruning ≈ 移除過度細分的資料庫索引／分區，分太細查詢在新資料上反而失準，要適度合併分支

08　名詞卡（後端翻譯詞典）
亂度Entropy

一張資料表裡「值有多雜亂」的指標：欄位值全相同（像單一常數欄位）亂度是 0；均勻分散（像 UUID 主鍵）亂度就很高。

資訊獲利Information Gain

幫你選「該用哪個欄位當分支條件」的依据：選能讓兩邊子集合最快變乾淨的欄位優先切。

Gini索引Gini Index

跟亂度是同一種「不純度」概念的不同計分方式，像同一個 KPI 換了一套公式，CART 演算法用它。

裝袋法Bagging

對同一張表做多次「取後放回」抽樣（像重複執行帶 RANDOM() 的 SELECT），各自訓練一個獨立模型。

提升法Boosting

像連續好幾輪的 code review：這輪漏掉的 bug，下一輪 reviewer 被要求特別盯著看，逐輪修正。

隨機森林Random Forest

多台掛在同一個 load balancer 後面的 worker，每台看到的資料列跟欄位都不完全一樣，最後用投票決定回應。

自適應提升AdaBoost

Boosting 的一種實作：明確調高上一輪答錯樣本的權重，像把上次失敗的 test case 標記 high priority 優先重跑。

修剪Pruning

移除過度細分的索引／分區：樹長太深就像分區分得過細，查詢在新資料上反而失準，要適度合併分支。

09　面試模擬

Q：什麼情況你會選 Random Forest，而不是單一決策樹？

A（草稿）：「以我做的 Threat Intel Agent 為例，如果想在呼叫昂貴的 Claude API 之前，先做一層本地端快速初篩，單一決策樹很容易對訓練資料過擬合——尤其資安特徵雜訊多，像有些異常的 PortScan 次數其實是合法的資安掃描工具造成的，單棵樹可能會為了遷就這種怪樣本切出一個只服務它的分支。Random Forest 透過 Bagging 對資料列跟特徵欄位都做隨機抽樣，組出多顆有差異的樹再投票，能降低單一雜訊樣本把整體判斷帶偏的風險，同時還保留了決策樹『可詮釋』的優點——能看 feature importance 知道到底是 AbuseIPDB 分數還是 PortScan 次數比較關鍵，訓練速度也夠快，適合放在真正呼叫 LLM 之前的初篩層，把明顯安全的 IP 先擋掉，省下 API 成本。」

10　效率檢查點

合上這頁，只憑 06 步驟那張心智圖的骨架（決策樹 → 修剪／Bagging／Boosting → Random Forest／AdaBoost），把每一個分支「怎麼抽樣、怎麼訓練、解決什麼問題」重新講一次，再用 03 步驟那 5 筆 IP 資料的亂度公式，親手把 Information Gain 重算一次。
