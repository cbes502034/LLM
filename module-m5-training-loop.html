訓練迴圈——把引擎裝進一台跑得動的車

M4 學會了梯度下降怎麼調整一個參數；但一顆真正能訓練、能重複執行的神經網路，需要有組織的結構（nn.Module）、明確的評分標準（Loss）、決定怎麼調的策略（Optimizer），還有一個標準化、可以重複跑一萬次的迴圈。這個模組把這台車組裝起來，也是你實際能寫出訓練程式碼、而不只是懂原理的關鍵一步。

01　為什麼要學這個

面試官問完梯度下降的原理，下一句通常是「那你有沒有實際訓練過模型」——這題考的不是背原理，是你會不會寫 nn.Module、選對 loss function、挑對 optimizer、寫出正確順序的訓練迴圈。這個模組把這些 PyTorch 裡最常被拿來出考題、也是你真的想做本地端小型分類器時一定要會寫的元件，一次補齊。

02　底層概念（先不談案例，只談最原始的東西）——一個函數的三個角色

完全先不談 PyTorch、不談神經網路。回到國中數學：y = wx + b。這個式子裡有三種角色——輸入（x）、參數（w 跟 b）、輸出（y）。給定一個 x 跟一組 w、b，就能算出一個 y。而「訓練」這件事，說穿了就是：固定 x，調整 w 跟 b，讓算出來的 y 越來越接近你心裡的正解。

階段w（權重）b（偏差）x（輸入）y = wx+b（預測）正解差距
一開始瞎猜0.500.0031.507.005.50
調整一次後1.800.5035.907.001.10
再調整一次2.001.0037.007.000.00（此例正解剛好是 y=2x+1）

這就是 nn.Module 最底層的地基——不管神經網路疊了幾百層、幾千萬個參數，每一層做的事情本質上都還是這個式子的變形：輸入、參數、輸出。M4 學的是「怎麼調整 w、b 這兩個參數」（梯度下降）；M5 要學的是「怎麼把很多個這樣的函數一層一層組織起來、怎麼系統化地重複這個調整過程」。

03　逐層往上疊——從函數到訓練迴圈

把很多個 y = wx + b 疊起來，中間插入一個非線性轉換（活化函數），就變成了神經網路。PyTorch 裡用 nn.Module 組織這件事：繼承 nn.Module，在 __init__ 裡宣告要用到哪些層，在 forward() 裡定義資料實際怎麼流過這些層。呼叫 model(x) 會自動觸發 forward()——不要直接呼叫 model.forward(x)。

元件作用
nn.Flatten把多維資料（例如影像）攤平成一維向量
nn.Linear線性變換，就是 wx + b
nn.ReLU非線性活化函數
nn.Sequential把多個層依序包成一個容器
nn.Softmax把輸出轉成加總為 1 的機率分布，常用在多分類的最後一層

光有網路結構還不夠，還需要兩個東西：Loss Function（這次預測差多少）跟 Optimizer（知道差多少之後，參數具體怎麼調）。這三個東西合起來，依照固定的五個步驟跑，就是訓練迴圈——這個迴圈有嚴格先後順序，每個 batch 都要重複一次：

決定「怎麼調」的 optimizer 有好幾種策略，彼此是互相獨立的選項：

優化器核心邏輯優點缺點／限制什麼情境選它
SGDweight = weight − lr×gradient，最基本版本邏輯簡單、好理解、好除錯容易在山谷型 loss 地形震盪，收斂慢教學、簡單模型，或想手動精細控制
Momentum模擬物理慣性，同方向加速、反覆方向減速減少震盪，收斂比 SGD 快多一個要調的超參數（動量係數）loss 地形有明顯山谷／峽谷狀時
AdaGrad依每個參數的歷史梯度平方和，自動調整各自學習率常變動的參數自動變穩、不常變動的參數學快一點訓練後期分母越加越大，學習率趨近 0，容易停滯特徵稀疏、各參數更新頻率差很大
Adam結合 Momentum＋AdaGrad，再加偏差校正大多數情境下收斂快又穩，不太需要手調相對吃記憶體（要存動量與二階矩）業界預設選擇，常見預設 lr=0.001
04　現在才代入具體案例

把上面的元件套進「這個 IP 是不是威脅」的貫穿案例。跟 M1／M2 用的是同一組結構化特徵——AbuseIPDB 分數、地理位置、PortScan 次數——這次用 nn.Module 定義一個很小的網路：

model = nn.Sequential( nn.Linear(3, 16), # 輸入3個特徵 → 16個隱藏神經元 nn.ReLU(), nn.Linear(16, 2) # 輸出2個類別的分數(safe / threat) )

forward 時，一批 IP 的 3 個特徵（AbuseIPDB 分數／地理位置編碼／PortScan 次數）流進去，經過第一層線性轉換變成 16 個神經元，ReLU 做非線性轉換，再經過第二層線性轉換，輸出 2 個分數。loss 用 CrossEntropyLoss（分類任務的標準選擇，不用 MSE，因為分類問題交叉熵的梯度表現跟收斂速度都更好）；optimizer 用 Adam，不特別調參，先用預設 lr=0.001。訓練迴圈跑起來：每個 batch 都執行一次 zero_grad → forward → loss → backward → step，重複幾個 epoch，loss 理論上會像 M4 步驟 03 的疊代表格一樣一路下降。

這就是「換神經網路做」這個階段真正落地的樣子——特徵沒有變，變的是不用你手動設計 IF-ELSE 規則或決策樹分支，而是讓 nn.Module 裡的權重透過訓練迴圈自動學出這三個特徵該怎麼組合。

05　類比鎖記憶——用後端維運場景掛住六個名詞
nn.Module（繼承+定義__init__/forward） ≈ 寫一個class繼承基底類別 　在__init__宣告要注入哪些元件（像FastAPI用Depends宣告依賴） 　在forward定義request怎麼依序流過這些元件（像middleware pipeline） 呼叫model(x)而非model.forward(x) ≈ 呼叫公開entry point、不繞過routing直接呼叫底層function 　框架在model(x)背後還掛了其他hook要跑 Loss Function ≈ health check / 監控指標，量化「目前系統狀態離預期差多遠」 Optimizer(如Adam) ≈ 自動調參的auto-scaling策略 　SGD像最陽春的線性調整，Adam像會參考歷史趨勢的智慧型調整策略 訓練迴圈五步驟 ≈ CI/CD pipeline，每個batch都固定跑一次：清狀態→跑一次→評分→算修正→套用 Dropout ≈ chaos engineering，訓練時隨機關掉部分節點 　逼系統不要過度依賴少數幾台機器/幾個神經元

特別注意 zero_grad() 這一步：PyTorch 預設會把新算出的梯度「累加」到 .grad 上，不像大部分後端框架每個 request 都是全新的 context——比較像如果你忘記在每個 request 開始時清空一個全域變數，上一個 request 的殘留值會混進這次的結果，所以每個 batch 開始前一定要先 zero_grad()。

應用領域具體產品／系統這個技術解決了什麼問題
優化器選擇幾乎所有主流框架訓練大型模型（含 GPT 等 LLM）Adam 是目前訓練大型模型的預設選擇，收斂快且不太需要手動調參。

08　名詞卡（後端翻譯詞典）
神經網路模組nn.Module

繼承這個基底類別，在 __init__ 宣告要用的層，在 forward 定義資料怎麼流過——像寫一個 class 繼承 framework 基底，用 Depends 宣告依賴、在請求處理函式裡定義流程。

損失函數Loss Function

量化「預測跟正解差多少」的一個數字——像系統的健康檢查指標，數字越低代表系統狀態越接近預期。

優化器Optimizer

知道梯度之後決定怎麼調整參數的策略——像 auto-scaling 演算法依監控指標決定怎麼調資源，Adam 是目前最常用的智慧型預設策略。

隨機丟棄Dropout

訓練時隨機關掉一部分神經元的輸出——像 chaos engineering 隨機關掉部分節點，逼系統不能只依賴少數幾個地方，藉此提升穩健度。

09　面試模擬

Q：你可以描述一下 PyTorch 訓練一個模型的標準流程嗎？為什麼要先做 optimizer.zero_grad()？

A（草稿）：「先用 nn.Module 定義網路結構，__init__ 裡宣告要用的層，forward() 裡定義資料怎麼流過去。訓練迴圈每個 batch 要固定跑五步：先 optimizer.zero_grad() 清空上一輪殘留的梯度，因為 PyTorch 預設會把新算的梯度累加到 .grad 上，不清空的話這一輪的梯度會疊加到上一輪殘留的值上，等於算錯。接著把資料丟進 model(x) 做前向傳播算出 predicted，用 loss function（分類任務通常用 CrossEntropyLoss）算出 loss，呼叫 loss.backward() 沿著 Autograd 建的計算圖反向傳播算出每個參數的梯度，最後 optimizer.step() 依照選定的優化器策略——我通常直接選 Adam，收斂快又不用太花時間調參——更新參數。如果之後要做一個小型 NN 來初篩 Threat Intel Agent 裡的 IP 風險，特徵還是 AbuseIPDB 分數、地理位置、PortScan 次數這三個，用 nn.Sequential 疊兩層 Linear 加 ReLU，loss 用 CrossEntropy，optimizer 用 Adam，就是一個可以先跑起來、之後再迭代的雛型，好處是可以擋掉一部分明顯安全的 IP，不用每次都呼叫 Claude API。」

10　效率檢查點

合上這頁，只憑 03 步驟那張五格流程圖（zero_grad → forward → loss → backward → step），重講一次為什麼每一步不能省略、順序不能換；再挑戰自己：不看範例，手寫一次一個只有兩層 Linear＋一個 ReLU 的 nn.Module class 骨架（__init__ 跟 forward 各寫一次）。兩件事都做得出來，才算真的把訓練迴圈的機制吃下去了，不是背下五個英文單字的順序。
